# Архитектура J.A.R.V.I.S.

## Схема

```
            ┌──────────── интерфейсы ────────────┐
 микрофон → │ голосовой цикл (main.py)           │
 консоль  → │ текстовый режим (--text)           │──► Assistant.handle(text)
 браузер  → │ HUD: web_app.py ⇄ WebSocket ⇄ web/ │        │
            └────────────────────────────────────┘        │
                                                          ▼
 ┌─────────────────────────── ядро (assistant.py) ───────────────────────────┐
 │ 1. аварийная остановка  2. подтверждение / выбор варианта  3. антиповтор   │
 │ 4. встроенные фразы     5. быстрые команды (intents.py, без модели)        │
 │ 6. сложная задача → провайдер модели:                                     │
 │      ollama  → цикл инструментов _ask_llm (локально)                      │
 │      ollama_cloud / gemini → тот же цикл инструментов через HTTPS        │
 │      team → параллельные текстовые ответы → ведущий → общий итог         │
 │      codex → текстовый ответ ChatGPT через Codex CLI                     │
 │      claude  → providers.ClaudeAgentBackend (Claude Agent SDK)            │
 │ Любой вызов инструмента: ToolRegistry.validate → лимиты → подтверждение → │
 │ handler → журнал (без приватных аргументов) → событие для интерфейса      │
 └──────────────────────────────────────────────────────────────────────────┘
                                   │
     ┌──────────────┬──────────────┼───────────────┬──────────────┐
     ▼              ▼              ▼               ▼              ▼
 web_tools.py   windows_control  memory.py      reminders.py   calculator /
 browser.py     (рабочий стол)   (SQLite)       notes.py       dictation
 web_search.py
     │
     ▼
 Chromium (Playwright, отдельный профиль data/browser-profile)
```

## Модули и ответственность

| Модуль | Ответственность | Не делает |
|---|---|---|
| `assistant.py` | маршрутизация реплики, цикл инструментов Ollama, подтверждения, события | не знает про аудио и HTTP |
| `ollama_cloud.py` | официальный API Ollama Cloud, авторизация из окружения, формат Ollama | не отправляет ключ локальному клиенту и не принимает произвольный адрес API |
| `intents.py` | шаблоны частых команд RU/EN → `Intent(tool, args)` | не вызывает инструменты сам |
| `tool_registry.py` | описание инструментов, типы, валидация, уровень разрешений, `ToolResult` с данными для UI | не исполняет код от модели |
| `browser.py` | один поток Playwright, очередь задач, постоянный профиль, номера элементов (`data-jarvis-ref`), понятные ошибки | не решает, что безопасно |
| `web_search.py` | поисковики через браузер, разбор YouTube (`ytInitialData` → DOM), честные ошибки (капча, согласие) | не придумывает результаты |
| `web_tools.py` | инструменты для реестра; проверки рискованных кликов и ввода; пометка текста страниц как недоверенного | |
| `providers.py` | слой провайдеров; Claude Agent SDK в изоляции (только инструменты Джарвиса) | |
| `site_studio.py`, `site_render.py`, `site_audit.py` | студия сайтов: фразы, поиск и разбор старого сайта в браузере (`ANALYZE_JS`: карточки товаров, JSON-LD, логотип), тексты моделью (JSON), фильтр выдуманных фактов, вёрстка одного `index.html`, оценки «до → после» | модель не пишет HTML и не придумывает цены и контакты |
| `team.py` | команда ИИ: участники Claude / ChatGPT (`codex exec`, только чтение, пустая папка) / Gemini / Ollama отвечают параллельно, ведущий сводит ответы; события `team` для HUD | участникам не даются инструменты Джарвиса |
| `web_app.py` | сервер HUD: очередь команд в отдельном потоке, рассылка событий, отмена, REST памяти и диагностики | не исполняет инструменты в обход ядра |
| `memory_io.py` | экспорт/импорт памяти в JSON: только добавление, фильтр секретов, белый список настроек | не меняет настройки безопасности |
| `schedules.py` | плановые задачи: расписание, журнал запусков, выполнение через `Assistant.run_unattended` | не выполняет действий, требующих подтверждения |
| `skills.py` | навыки: SKILL.md → инструкция + маски инструментов; выбор по фразе; `use_skill` | не добавляет прав и не запускает скриптов |
| `files.py` | файлы в разрешённых папках: чтение, поиск, изменения через diff + подтверждение, резервные копии | не выходит за `allowed_dirs`, не читает секреты |
| `mcp_client.py` | внешние MCP-серверы из конфига: процесс по stdio в отдельном потоке asyncio, белый список инструментов → реестр, ответы как недоверенные | не пускает инструменты сервера в обход реестра |
| `config.py` | `config.toml` + личный `config.local.toml` поверх (рекурсивное слияние), запись TOML | |
| `updater.py` | `update.bat`: правки `config.toml` → `config.local.toml`, `git fetch` + только fast-forward, доустановка пакетов по изменённым `requirements*.txt`; `check()` и `UpdateChecker` для HUD (только смотрят) | не трогает чужие изменения, не сливает разошедшуюся историю |
| `sysinfo.py` | загрузка ЦП/ОЗУ (psutil) и видеокарты (nvidia-smi, не чаще раза в 5 с) для верхней панели HUD | чего нет — None, HUD это поле не показывает |
| `supervisor.py` | `run_web.bat` → запуск HUD; код выхода 75 («Обновить и перезапустить») → `updater --from-hud` после выхода Джарвиса → снова запуск | только стандартная библиотека: обновление может заменить любой файл |
| `memory.py` | SQLite: факты, настройки, заметки, напоминания; фильтр секретов | |
| `vault.py` | заметки Obsidian (`[memory.vault]`): проекты, цели, задачи, решения, проверки — файлы Markdown (владелец — файл, в SQLite `vault_notes` только индекс); зеркало `Джарвис/*.md` из memory.db; указатели `INDEX.md`; инструмент `save_memory_note` | не читает правки зеркала обратно в базу, не пишет секреты |
| `web/orb.js` | сфера HUD: свой WebGL (без библиотек), запасной Canvas 2D, `prefers-reduced-motion`, авто-качество со снижением на медленной машине; сигнал — уровень микрофона или огибающая голоса Silero (`/api/audio/level` → `speech`), иначе подписанная анимация состояния | не изображает громкость, которой нет |

## Ключевые решения

1. **Остаёмся на Python.** Ядро, голос, тесты и CI уже работали на Python; Playwright, Starlette и
   Claude Agent SDK есть для Python. Переписывание на Node/TypeScript не дало бы функциональности.
2. **HUD без сборки** (HTML + CSS + ES2020, без React/Vite и CDN). Пользователю на Windows не нужен
   Node.js; интерфейс работает офлайн; меньше зависимостей. Если интерфейс разрастётся — можно
   перейти на Vite, API (WebSocket-события) от этого не изменится.
3. **Playwright sync API в выделенном потоке.** Sync-объекты Playwright привязаны к потоку;
   голосовой цикл, HUD и агент Claude ставят задачи в очередь `BrowserController.call`.
4. **Элементы по номерам из DOM**, а не по координатам: JS помечает видимые интерактивные элементы
   атрибутом `data-jarvis-ref` и возвращает роль, тип и доступное имя (aria-label, label, placeholder,
   текст). После перехода номера пересчитываются (`read_page`). Скриншот — запасной вариант.
5. **Поиск через браузер, без ключей.** DuckDuckGo HTML → Bing. В фоновом (headless) режиме DuckDuckGo
   показывает капчу, поэтому браузер Джарвиса по умолчанию видимый. YouTube — из `ytInitialData`.
6. **Простые команды без модели.** «Открой YouTube и найди …» → `youtube_search` за ~2–5 с без LLM.
   Признаки многошаговой задачи (`сравни`, `прочитай`, `потом`, `дай вывод`, длинная фраза) отправляют
   запрос модели (`assistant.is_complex_request`).
7. **Провайдер Claude через официальный Agent SDK** (`ClaudeSDKClient`): `tools=[]` (встроенные
   инструменты Claude Code выключены), `setting_sources=[]` (без пользовательских настроек, плагинов,
   CLAUDE.md), `strict_mcp_config`, `allowed_tools` = только `mcp__jarvis__*`, `can_use_tool` отклоняет
   всё остальное. Инструменты Джарвиса — in-process MCP-сервер, обработчик вызывает тот же
   `Assistant._run_tool` (валидация, лимиты, подтверждения, журнал). Контекст между ходами — `resume`.
   Отмена — `client.interrupt()`. Независимые части задачи Claude может поручить агентам Джарвиса
   (`AGENT_ROLES`: researcher, file-reader) — у каждого только читающие инструменты; встроенные агенты
   Claude Code запрещены; агенты выполняются синхронно (`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`).
8. **Подтверждения едины для всех путей.** Опасное действие не выполняется, а регистрируется в
   `ConfirmationManager`; модель получает «нужно подтверждение» и заканчивает ход; кнопка
   «Подтвердить» в HUD отправляет фразу подтверждения — тот же путь, что голосом.
9. **Сервер только на 127.0.0.1**, проверка `Host` (DNS rebinding) и `Origin` (чужие сайты) для
   WebSocket и REST. Удалённого доступа нет: для него нужна отдельная аутентификация.

## События интерфейса (WebSocket `/ws`)

Сервер → клиент: `hello` (состояние, история), `task`, `state` (`idle|thinking|acting|error`),
`delta` (поток текста), `tool_start` / `tool_end` (имя, аргументы без приватных, результат, `data`),
`confirm` (с `details` — например, diff файла), `confirm_resolved`, `reply` (текст, `data`, `pending_confirmation`), `cancelled`, `notice`, `skill` (включён навык), `delegate` (поручение агенту), `site` (задача студии сайтов: шаги, результат, предложения), `team` (команда ИИ: ответ и время каждого участника, ведущий, итог), `memory` (что из памяти ушло модели: запрос, записи, связанные заметки), `memory_saved` (записана заметка Obsidian); у `task`/`reply` плановой задачи — `scheduled: true`.

Клиент → сервер: `message`, `cancel`, `confirm` (`answer: true|false`), `tool` (только кнопки из
белого списка `UI_TOOLS`, например `open_result`).

`data.kind`: `youtube`, `web` (items с url/title/…), `page`, `opened`, `screenshot`, `tabs`, `mcp`, `files`, `file`, `diff`, `file_changed`, `error`.

## Уровни разрешений

| Уровень | Примеры | Поведение |
|---|---|---|
| auto | поиск, чтение страницы, переход, прокрутка, вкладки, калькулятор | сразу |
| conditional | `browser_click`, `browser_type` | подтверждение, если кнопка «Купить/Отправить/Удалить/Оплатить…», поле пароля, отправка из многострочного поля |
| confirm | удаление файла, закрытие окна, выключение ПК, очистка памяти, `files_write`/`files_edit` (с diff) | всегда подтверждение |
| MCP | инструменты внешних серверов из `allowed_tools` | `auto_tools` — сразу, остальные — всегда подтверждение |
| плановая задача | всё, что требует подтверждения | не выполняется (отказ модели), пользователь видит это в итоге |
| нет инструмента | shell, sudo, произвольный код, чтение личного профиля браузера | недоступно модели вообще |

## Допущения

* Один пользователь, локальная машина. Многопользовательский и удалённый доступ не поддерживаются.
* Целевая система — Windows 10/11.
* Модель Claude — алиас `sonnet` (Claude Code сам сопоставляет его с актуальной моделью); можно указать
  полный идентификатор в `[llm.claude] model`.
