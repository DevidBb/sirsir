# Дорожная карта

Отметка ✅ ставится, только если функция реализована и проверена (тестом или реальным запуском).

## Этап 1 — рабочее ядро и браузер ✅ (2026-10-16)

- ✅ Интерфейс HUD (`python -m jarvis --web`): чат с потоковым выводом, состояние, ход задачи,
  карточки результатов, подтверждения, отмена, память, настройки моделей, диагностика.
- ✅ Браузер Джарвиса (Playwright, свой профиль): открыть адрес, вкладки, чтение страницы с
  номерами элементов, клик, ввод, клавиши, прокрутка, назад, скриншот.
- ✅ Поиск в интернете (DuckDuckGo → Bing) и на YouTube без API-ключей; «открой N-й результат».
- ✅ Слой провайдеров: Ollama (локально) и Claude Agent SDK (изолированно, только инструменты Джарвиса).
- ✅ Простые команды без модели, сложные — модели (план → действия → проверка → ответ).
- ✅ Подтверждение рискованных браузерных действий; запрет секретов в памяти; Origin/Host-защита.
- ✅ Тесты: 526 быстрых + 11 с реальными моделями (в т.ч. настоящий Chromium на локальной странице, сервер HUD, Claude SDK с
  подставным клиентом); CI на Windows.
- Проверено вручную на машине разработки (2026-10-16): YouTube-поиск и открытие видео, поиск с источниками,
  многошаговая задача в Википедии через Claude, отмена за ~3 с, честная ошибка при выключенной Ollama.

Целевая система — **только Windows** (решение пользователя 2026-10-16). Linux-версия не делается;
поведение на Windows проверяется в CI на настоящей Windows.

## Этап 3 — память

- ✅ Типы памяти: предпочтения, факты, заметки, итоги задач (+ журнал действий `data/actions.log`).
      «Запомни, что…» — без модели, предпочтение определяется по словам («предпочитаю», «всегда», «отвечай»…).
- ✅ Полнотекстовый поиск (SQLite FTS5, индекс ведут триггеры; без FTS5 — LIKE), инструмент модели
      `search_memory`, поиск во вкладке «Память». В промпт: все предпочтения + до 15 фактов целиком,
      при большой памяти — только найденное по запросу. Старые базы мигрируют автоматически.
- ✅ Итоги многошаговых задач (запрос → результат, инструменты) сохраняются автоматически, без секретов;
      видны и удаляются в HUD; отключение — `[memory] task_summaries = false`. Проверено вживую с Claude.
- ✅ Экспорт/импорт памяти (`jarvis/memory_io.py`, HUD → Память → «Перенос памяти»): JSON с фактами,
      предпочтениями, заметками, итогами задач, напоминаниями, плановыми задачами и голосовыми
      настройками. Импорт только добавляет, повторы и секреты пропускает, плановые задачи — выключенными,
      настройки безопасности/папок/сети не меняет.

## Этап 4 — расширяемость

- ✅ Внешние MCP-серверы из `config.toml` (`[mcp.servers.*]`, stdio, официальный пакет `mcp`):
      белый список `allowed_tools`, без подтверждения — только `auto_tools`, токены из `.env` по именам.
      Инструменты попадают в общий реестр (`mcp_<сервер>_<инструмент>`), поэтому работают и с Ollama,
      и с Claude, с той же проверкой аргументов, лимитами, журналом и подтверждениями. Ответы — в
      `<untrusted>`. Состояние в HUD → Диагностика. Проверено с настоящим процессом сервера и вживую с Claude.
- ✅ Навыки (`jarvis/skills.py`, `skills/<имя>/SKILL.md`, формат Skills Claude + `triggers`, `tools`,
      `max_steps`): запуск фразой или «навык <имя> …», в навыке модель видит только его инструменты
      (Ollama и Claude), каталог навыков в промпте и инструмент `use_skill`; список и «перечитать» в HUD.
      В комплекте: `research`, `project-review`, `video-pick`. Проверено вживую с Claude (research).
- ✅ Поручения агентам (Claude, `AgentDefinition`): «исследователь» (internet_search, youtube_search,
      fetch_page) и «аналитик файлов» (files_list/read/search) — только читающие инструменты, работают
      параллельно, синхронно (ход ждёт их отчётов). Встроенные агенты Claude Code запрещены
      (`can_use_tool`). Браузер: чтение во временных вкладках (`fetch_page`), составные действия под
      замком; у чтения отдельный лимит в минуту. Текст агентов в ответ не попадает — главный агент
      сводит отчёты. Проверено вживую: 3 агента, сравнение Rust/Go/Zig со ссылками за ~40 с.
- ✅ Плановые задачи (`jarvis/schedules.py`, SQLite): каждый день / будни / выходные / дни недели /
      каждые N минут (от 15) / разово; вкладка «Расписание» в HUD (создать, включить/выключить,
      запустить сейчас, удалить, журнал запусков); инструменты `schedule_task` (с подтверждением),
      `list_schedules`, `cancel_schedule`. Выполнение без пользователя: отдельный диалог, действия с
      подтверждением не выполняются; пропуск больше часа не догоняется. Проверено вживую с Claude.
- ✅ Файлы и проекты в `[files] allowed_dirs` (`jarvis/files.py`): `files_list`, `files_read`, `files_search`
      сразу; `files_write`/`files_edit` — после diff в HUD и подтверждения (3 мин), резервная копия,
      отказ, если файл изменился после показа diff; секреты не читаются, запускаемые файлы и `.git` не
      меняются; CRLF и кодировка (UTF-8/BOM/cp1251) сохраняются. Проверено вживую с Claude: нашёл и
      исправил ошибку в коде после подтверждения.

## Скорость

- ✅ Постоянная сессия Claude (`ClaudeAgentBackend`): клиент SDK живёт между ходами в своём потоке,
      запускается заранее (`[llm] preload`). Замер на dev-машине (haiku): было ≈6.7 с на ход, стало
      1.7–3.5 с, включая вызов инструмента. Найденная по запросу память теперь в самом запросе, а в
      системном промпте — только постоянная (предпочтения, факты), чтобы промпт не менялся.

## Известные ограничения

- В headless-режиме DuckDuckGo показывает капчу — браузер по умолчанию видимый.
- YouTube в некоторых регионах показывает страницу согласия: её нужно принять один раз вручную
  в окне браузера Джарвиса (профиль запомнит выбор).
- Голосовой ввод в HUD — Web Speech API браузера (облако Google в Chrome/Edge; в Firefox нет).
- Провайдер Claude держит процесс Claude Code между ходами и запускает его заранее при старте; он
      перезапускается (≈5 с) при смене навыка, после «нового диалога», плановой задачи или ошибки.
- Ход агента Claude ограничен `[llm.claude] max_turns` и `timeout_seconds`.
